3 Approaches for FocusRail in Video Works

All three keep the filterable grid below. The difference is how the FocusRail itself is built.

A

Clean Vanilla JS Port ★ Recommended

Write a new self-contained VideoFocusRail class in Script.js that mirrors FocusRail's behavior — 3D coverflow transforms via JS, CSS transitions for spring-like physics, blurred poster ambience background, drag/swipe/keyboard/wheel input. Clicking center card calls the existing openVideoModal(). The EtherealCarousel stays untouched for the portfolio section.

Pros

  • Zero new dependencies
  • Fits existing code style
  • No build step needed
  • Portfolio carousel unaffected

Cons

  • Spring physics less precise than framer-motion
  • ~150 lines of new JS
B

CSS-first with thin JS driver

Define all 3D transforms in CSS using --offset custom properties per card. JS only updates one number per card on navigation. Smoother on low-end devices; animation entirely GPU-driven. Background ambience still done in JS.

Pros

  • Most performant option
  • Cleanest JS (~80 lines)
  • Easy to tweak in DevTools

Cons

  • Per-card CSS rules get verbose
  • Harder to add per-card dynamic values (blur, brightness)
C

Extend EtherealCarousel with a "focusRail" mode

Add a mode: 'focusRail' option to the existing EtherealCarousel class. When active, the class applies FocusRail-style 3D offsets instead of its current flat offset logic. One class, two modes.

Pros

  • Least new code overall
  • Reuses existing input handling

Cons

  • Risks destabilising the portfolio carousel
  • Mixed concerns in one class
  • Harder to reason about

My recommendation: A. It's the safest and most maintainable path — a purpose-built class that mirrors exactly what FocusRail does, without touching any existing code. The physics approximation with CSS easing is imperceptible to end users.
