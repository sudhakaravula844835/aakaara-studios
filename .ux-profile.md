# UX Profile

Generated by `setup-ui-ux-skills`. All UI/UX skills in this project read this file before changing layout, copy, or interaction.

## Aesthetic reference

- **Standard:** Custom <!-- Linear | Stripe | Apple Native | Raycast | Notion | Custom -->
- **Notes:** Cinematic editorial for a South Asian wedding photo/film studio.
  - Dark, film-like canvas (`--noir` #09080b, `--umber`) with warm gold accents (`--rose` #c9956b, `--rose-light`, `--blush`); light sections on `--ivory` / `--champagne` / `--parch`.
  - Type: `--font-display` Cormorant Garamond for headings and editorial moments; `--font-body` Outfit for UI and body. A few weights, large display sizes, generous leading.
  - Generous whitespace, imagery first, one gold accent per view. The photo or film is always the hero, and chrome stays quiet.
  - Motion is slow and eased (`--ease`, `--ease-smooth`), cinematic rather than snappy, and always has a reduced-motion fallback.
  - `/board` (CRM: Owner, PM, Editor and Client views) uses the same palette and type but runs calmer and denser: readable tables, no decorative motion.
  - Reuse the tokens in `styles.css` `:root`. Don't add new hex values when a token exists.

## Banned anti-aesthetics

- Glassmorphism / `backdrop-filter` **without a high-contrast boundary**. Frosted glass is allowed only with a hard edge (border or solid outline) and text that meets AA on the blurred backdrop. The existing frosted "VIEW" gallery pill is the reference case.
- Floating pastel pill badges for ordinary metadata
- Arbitrary decorative gradients and neon glowing borders. Functional scrims (dark gradients that keep text readable over photos and video) are allowed.
- Multi-color radial rainbow gradients on CTAs
- Decorative blob / mesh gradients behind content
- Cartoon empty-state illustrations (people waving / high-fiving); huge centered illustrations with no CTA
- Nested scrollbars (page + card + list all scrolling)
- Icon bloat inside inputs (only search, clear, password reveal)
- Soft drop shadows as the only separator (no border)
- Disabled primary submit as the only incomplete-form feedback

## Accessibility target

- **Level:** WCAG 2.1 AA <!-- WCAG 2.1 AAA | WCAG 2.1 AA -->
- **Contrast:** 4.5:1 for normal text, 3:1 for large text, borders and UI. Follow the Nov 2026 contrast tokens in `CLAUDE.md`: on ivory/cream use `--bronze-deep` for body-size gold text, `--bronze` for large text and field outlines, and `--saffron-deep` for saffron text (`--rose` is only about 2:1 there). On dark, secondary text uses `--ivory-soft`. Gold buttons take `--noir` text.
- **Touch / focus:** 44×44px minimum targets; refined but always visible focus rings; overlays (video modal, project modal) trap focus and restore it on close.

## Brand tone and microcopy voice

- **Voice:** Warm & Humancentric <!-- Utilitarian & Minimal | Warm & Humancentric | Opinionated & Direct -->
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Speak to couples and families like a trusted friend behind the camera: clear, warm, never salesy or gushing. Board copy for staff stays plain and practical. Errors never blame the user and always offer a next step.

## Icon library

- **Library:** Project SVG <!-- Lucide | Heroicons | Phosphor | Tabler | Radix Icons | Remix Icon | Project SVG | None -->
- **Package / path:** Inline `<svg>` in the HTML (`index.html`, `couple-portraits.html`, `board/`). No icon package installed.
- **Notes:** Keep to the existing thin-stroke inline style (`stroke="currentColor"`, 16–24px). No icon packages mixed in, and no emoji as UI icons.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
